# **Why we don’t need `&` when looping through an array, but we do need it for a vector**

### Short Answer

Arrays and vectors behave differently with ownership.

- **Arrays** implement the `Copy` trait (when their elements do).  
  So when you write `for fruit in fruits`, Rust **copies** the values. The original array stays usable.

- **Vectors** do **not** implement `Copy`.  
  So when you write `for fruit in fruits` (without `&`), Rust **moves** the values out of the vector. After the loop, the vector is no longer usable.

That’s why the documentation shows:

**Array (no `&` needed):**
```rust
let fruits = ["apple", "banana", "orange"];

for fruit in fruits {          // copies the values
  println!("I like {}.", fruit);
}

// fruits is still usable here
```

**Vector (`&` is recommended):**
```rust
let fruits = vec!["apple", "banana", "orange"];

for fruit in &fruits {         // borrows the values
  println!("I like {}.", fruit);
}

// fruits is still usable here
```

### More Detailed Explanation

| Feature              | Array                          | Vector                          |
|----------------------|--------------------------------|---------------------------------|
| Size                 | Fixed                          | Can grow/shrink                 |
| Ownership behavior   | Usually **copied**             | **Moved** by default            |
| Loop without `&`     | Safe (copies)                  | Moves ownership → vector becomes unusable |
| Loop with `&`        | Also possible, but not needed  | Recommended (borrows)           |

### What happens if you omit `&` with a vector?

```rust
let fruits = vec!["apple", "banana", "orange"];

for fruit in fruits {   // ownership is moved
  println!("{}", fruit);
}

// This will cause an error:
// println!("{:?}", fruits);  // error: value borrowed here after move
```

### Summary

- Arrays → values are copied → no need for `&`
- Vectors → values are moved → use `&` to borrow them so you can still use the vector later

That’s the key difference.
